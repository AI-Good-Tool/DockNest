# DockNest 2.7.0 · 独立应用文件夹

macOS 26 原生 SwiftUI + AppKit 应用。**一个 `.app` 就是一个文件夹，一个独立 Dock 图标。** 无第三方依赖。

## 安装 DMG

打开 `dist/DockNest-2.7.0-macOS-arm64.dmg`，退出旧版入口，将 `DockFolder.app` 拖到 `Applications`，再从应用程序目录启动。安装包仅含程序和安装说明，不含个人应用列表。本机签名，未公证。

## 管理多开与恢复

右上角 `…` → **管理多开文件夹**（菜单栏与 Dock 右键也提供入口）：

- **打开**：重新启动已存在的文件夹。
- **恢复并打开**：入口被移走或删除时，按已保存的列表重建 `.app`，保持原身份和数据；不需要读取整个废纸篓。
- 条目的 `…` → **更新到当前版本并打开**：为旧版独立入口安装当前代码，保留名称与应用列表。
- 旧版入口会标出版本号，主按钮直接变为 **更新并打开**；有旧版时顶部显示 **全部更新**。新版首次启动发现旧版入口时会提示一次。
- 当前文件夹若还有同身份的旧副本（例如主入口改过名，又另装了新的 `DockFolder.app`），显示 **更新旧副本**，原地替换为当前版本，Dock 中固定的图标继续可用。只处理 `/Applications`、`~/Applications` 中的副本。
- 同一文件夹有多个入口时（同身份的多份 `.app` 会互相抢占打开与退出），管理页提示 **只保留当前** 或 **改用另一份**；被移走的入口进入废纸篓，列表和设置不受影响。
- 管理页等弹层打开时，Dock「退出」与 `⌘Q` 会先收起弹层再退出。
- 条目的 `…` → **删除文件夹及全部数据**：确认后退出目标，删除可定位的入口、列表、设置、缓存和对应改名备份。
- **删除其他多开**：批量删除其他多开，保留当前文件夹和默认主入口。

无法定位的手工副本、废纸篓中的不可访问副本及手动固定的 Dock 图标仍需手动移除。文件夹中的真实应用不受影响。删除后无法从列表恢复。数据损坏时仍显示该记录，并阻止用空列表恢复。

## 使用新版

1. 退出之前打开的旧版 DockFolder。
2. 把 `build/Release/DockFolder.app` 复制到自己的「应用程序」目录，再启动。
3. 点击窗口右上角 `…` → **修改应用名称…**，输入例如「开发工具」。保存后该文件夹自动重新打开，Dock 和 Finder 使用新名称。
4. `…` → **新建独立文件夹…**，输入例如「聊天软件」。新的 `.app` 自动创建并打开，可以和其他文件夹同时运行。
5. 分别右键这些 Dock 图标 →「选项 → 在程序坞中保留」。

新建的文件夹应用位于 `~/Applications/DockFolders/`；菜单中的「在 Finder 中显示此文件夹应用」可以找到它们。请用「新建独立文件夹」创建新的入口；直接在 Finder 复制同一个 `.app` 会沿用原身份和原数据，不会产生新文件夹。

## 管理应用

- 点击「添加应用」多选 `.app`，或从 Finder 拖入应用/应用替身。也可拖到对应的 Dock 图标。
- 点击图标启动应用；支持搜索及回车打开第一个匹配项。
- 按住图标拖动可调整顺序，其他图标实时让位，松手即保存；拖到网格上下边缘会自动滚动。搜索时不可拖动。
- 右键图标：打开、在 Finder 显示、移到最前、从文件夹移除。
- Esc、关闭按钮或切换到其他应用收起面板；再次点击 Dock 图标展开。
- Dock 图标动态显示此文件夹前四个应用的缩略图。
- 窗口顶部显示与运行中的应用/Dock 一致的名称，不再显示英文副标题和分组栏。
- 缩小行间距与上下留白；600 × 440 默认窗口完整显示 3 行、每行 5 个图标，更多应用可滚动。
- `⌘N` 新建独立文件夹，`⌘O` 添加应用，`⌘F` 搜索。

原应用保留在原来的位置。移除快捷方式不会卸载应用。

## 备份

`…` → **设置** → **备份**：

- **导出备份…**：将此文件夹的应用列表（含顺序）保存为 JSON。
- **导入备份…**：选择备份文件后可 **合并**（只追加没有的应用）或 **替换**（与备份完全一致）。应用按书签、路径、bundle ID 依次在本机重新定位，找不到的会跳过并列出。也可直接导入其他文件夹数据目录中的 `library.json`。

## 改名与多开

每个新建应用都有独立 UUID、bundle identifier 和数据目录，因此可以同时运行、分别固定到 Dock。名称可以反复修改；改名保持身份、应用次序和数据目录不变，只自动重开当前文件夹。

改名会预先准备并验证签名，然后由独立辅助进程在原应用退出后替换内容。保留外层 `.app` 目录的文件身份，便于 Finder/Dock 的书签跟随改名；不重启 Dock、不改写 Dock 偏好设置。若系统仍缓存了旧标签，可将该图标重新拖入 Dock。

同目录已有同名 `.app` 时拒绝覆盖。失败时尝试恢复原应用与列表。恢复用原应用内容保存在 `~/Library/Application Support/DockFolder/Renames/`。应用需位于当前用户可写目录。

## 数据与旧版兼容

每个文件夹的列表保存在：

```
~/Library/Application Support/DockFolder/Instances/<UUID>/library.json
```

默认入口使用 `Instances/default/library.json`。首次运行新版时，将旧版当前选中的分组复制到该目录。旧版 `~/Library/Application Support/DockFolder/library.json` 完整保留，不会覆盖；如果旧版有其他分组，它们仍保存在此原始文件中，可根据该文件重新创建对应的独立文件夹。

JSON 原子写入；读取损坏数据失败时停止写入，避免覆盖原始内容。

## Xcode 开发

使用 Xcode 26 或更新版本打开 `DockFolder.xcodeproj`，选择 `DockFolder` scheme、`My Mac`，按 `⌘R`。部署目标 macOS 26.0。默认本机 ad-hoc 签名，无需开发者账号。

```sh
zsh "scripts/build.sh"
zsh "scripts/test.sh"
zsh "scripts/package-dmg.sh"
```

发布构建输出 `build/Release/DockFolder.app`。脚本只为当前命令选择 Xcode，不修改系统 `xcode-select` 设置。`Package.swift` 用于数据与应用实例测试，图形应用使用 Xcode 工程构建。

- `AppDelegate.swift`：生命周期、Dock 入口、面板与菜单。
- `FolderView.swift`：紧凑的应用网格、搜索及名称编辑。
- `FolderStore.swift`：应用选择、启动、状态与旧数据迁移。
- `InstanceCatalog.swift`：多开索引、发现、恢复、更新和限定范围的数据清理。
- `InstanceManagerView.swift`：管理列表与删除确认。
- `FolderInstance.swift`：独立应用生成、名称验证、签名、改名和恢复。
- `Library.swift`：数据模型与原子持久化，保留旧版数据兼容。
- `DockIcon.swift`：AppKit 文件夹图标绘制。

按界面、应用服务、实例管理、数据存储划分职责；复用名称验证和应用签名逻辑，保持无数据库、无额外常驻服务的实现。

## 验证与分发

自动测试覆盖去重、数据保存、实例隔离、同名冲突、中文名称、改名后的身份与目录保持、失败恢复。手动检查两个真实实例同时运行，以及通过界面修改名称、自动重启、列表保留和精简后的布局。

当前是本机签名版本，未经过 Developer ID 签名、公证或 App Store 分发。生成独立应用使用系统 `/usr/bin/codesign` 进行本机签名。无需辅助功能、录屏或完整磁盘访问权限。

## 开机自启动与运行圆点

右上角 `… → 设置`（或 `⌘,`）提供开机自启动开关，使用 macOS 系统登录项服务，每个独立文件夹单独配置，默认不主动开启。等待批准时显示系统实际状态，可打开系统登录项设置检查。建议先安装到固定的应用程序目录后再开启。删除可定位的新版入口前会移除该入口的登录项。若入口已完全丢失，应先恢复入口后关闭登录项，或直接在系统登录项中移除残留项。

Dock 圆点由系统绘制，公开接口不能只隐藏某个运行中应用的圆点。设置页提供「桌面与程序坞」入口与全局关闭说明；不会自动修改整个 Dock，也不会连同文件夹入口一起隐藏。

## 退出后保留缩略图

当前文件夹的前四个应用会合成为多分辨率 `.icns`，缓存到此实例数据目录的 `FolderIcon.icns`。正常退出时，独立辅助进程在原进程结束后写入签名完整的应用资源，更新图标资源名以刷新系统缓存。未运行时，Dock 由 Apple 的 `NSDockTilePlugIn` 机制读取同一份缓存并原样绘制，主应用无需运行；插件由系统宿主加载，不会让主应用出现运行圆点。Finder 仍使用系统处理的静态图标，可能显示灰色底板。

要同时消除运行圆点，请在 `…` 中选择「退出此文件夹」。仅按 Esc 或关闭按钮会收起窗口，进程仍然运行。首次升级后需要打开再正常退出一次来生成当前列表的静态图标；强制结束进程可能保留上一次静态图标。开机自启动开启时，下次登录后仍会成为运行状态。

更新和删除入口会等待正在进行的图标写入完成；图标写入不会改动应用列表。恢复、改名和升级会复用该实例的图标缓存，新建空文件夹使用默认图标。

### 2.4 的首次 Dock 刷新

旧版固定项目可能缓存着没有插件的配置。首次升级后，将对应图标从 Dock 移除，再从 Finder 将同一个 `.app` 拖回原位置一次（不删除 `.app` 或应用列表）。每个多开入口均需更新到 2.4 或更高版本。

`DockTilePlugin/DockTilePlugin.m` 只负责显示缓存图像；每个实例注册独立的 principal class，防止系统在同一宿主中加载多个插件时串用图标。应用在更新缓存后发送按实例区分的通知，插件无需定时轮询。`FolderInstance.configure` 同步插件身份并从内到外签名。Xcode 构建阶段会自动编译并嵌入插件，无需最终用户安装开发工具。

构建后运行 `zsh scripts/test-dock-plugin.sh`，验证两个真实插件在同一进程中的加载、独立图像和签名。
